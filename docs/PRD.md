## 1. 問題陳述

### 賓客端
喜宴上的招牌菜（佛跳牆、紅蟳米糕等）常讓賓客念念不忘，但宴席結束後就買不到；想在家重現，只能另找餐廳或自己費工料理。

### 會館端
- 婚宴會館的營收高度依賴檔期（農民曆好日子、週末），平日與淡季產能閒置。
- 宴席帶來大量潛在顧客，但會館沒有管道把「吃過一次的賓客」變成「回購的顧客」。
- 若線上、線下各自銷售，會員、點數、庫存分開管理，容易超賣、對帳困難。

### 機會
把暢銷菜色製成冷凍調理包，用喜宴現場的 QR code 把賓客導入線上商店，並以統一的會員與庫存整合線上線下（OMO），把一次性的宴席體驗延伸成持續的零售營收。

## 3. User Stories 與驗收條件

### US-01 喜宴 QR code 掃碼購買（MVP）
**身為**賓客，**我想要**掃描喜宴桌卡上的 QR code 直接購買剛吃到的菜，**以便**在家重現宴席美味。

- **情境 1：正常購買**
  - **Given** 賓客用手機掃描某場宴席的 QR code
  - **When** 進入落地頁並將商品加入購物車、完成付款
  - **Then** 訂單成立，`channel` 為 `qr`，並記錄該場宴席的 `event_id`
- **情境 2：宴席限定優惠**
  - **Given** 該場宴席設定了限定優惠券，且仍在有效期間內
  - **When** 賓客從 QR 落地頁進入結帳
  - **Then** 系統自動套用優惠，並顯示折扣後金額
- **情境 3：QR code 失效（例外）**
  - **Given** QR code 對應的宴席不存在或優惠已過期
  - **When** 賓客掃碼
  - **Then** 顯示「此優惠已結束」，仍可用一般價格購買，不顯示錯誤頁

### US-02 線上購買冷凍宅配（MVP）
**身為**家庭採買者，**我想要**在線上選購調理包並冷凍宅配到府，**以便**省下準備宴客菜的時間。

- **情境 1：正常結帳**
  - **Given** 購物車內有庫存足夠的商品
  - **When** 填寫收件資料並以綠界完成付款
  - **Then** 訂單狀態變為 `paid`，會員收到訂單確認通知
- **情境 2：庫存不足（例外）**
  - **Given** 結帳時某商品庫存少於購買數量
  - **When** 送出訂單
  - **Then** 訂單不成立，提示「庫存不足，目前剩 N 份」，購物車保留其他商品
- **情境 3：配送限制（輸入邊界）**
  - **Given** 使用者選擇配送方式
  - **When** 查看可用選項
  - **Then** 只顯示「冷凍宅配」與「會館門市自取」，不提供常溫超商取貨
- **情境 4：付款失敗或逾時（例外）**
  - **Given** 訂單為 `pending_payment`
  - **When** 付款失敗或超過付款期限（待確認：30 分鐘）
  - **Then** 訂單轉為 `cancelled`，保留的庫存自動釋放

### US-03 線上下單、門市自取（MVP）
**身為**住在會館附近的顧客，**我想要**線上下單後到會館自取，**以便**省運費並確保冷凍品質。

- **情境 1：正常自取**
  - **Given** 訂單選擇門市自取，且狀態為 `ready_for_pickup`
  - **When** 顧客出示取貨 QR code，門市人員掃描核銷
  - **Then** 狀態變為 `picked_up`，門市庫存扣除
- **情境 2：重複核銷（例外）**
  - **Given** 訂單已是 `picked_up`
  - **When** 再次掃描同一個取貨 QR code
  - **Then** 顯示「此訂單已於 YYYY/MM/DD HH:mm 取貨」，不重複扣庫存

### US-04 統一會員與點數（MVP）
**身為**會員，**我想要**線上和門市消費都累積到同一個點數帳戶，**以便**下次消費折抵。

- **情境 1：跨通路累點**
  - **Given** 會員以同一支手機號碼在線上與門市消費
  - **When** 訂單完成
  - **Then** 點數累積到同一帳戶，`point_ledger` 留有每筆異動紀錄
- **情境 2：點數不足（輸入邊界）**
  - **Given** 會員剩餘點數少於要折抵的點數
  - **When** 嘗試折抵
  - **Then** 最多只能折抵剩餘點數，且折抵後金額不得小於 0

### US-05 門市 POS 現場銷售（MVP）
**身為**門市人員，**我想要**在 POS 上現場結帳並即時扣除共用庫存，**以便**避免線上賣出門市已售完的商品。

- **Given** 門市人員在 POS 選取商品並完成收款
- **When** 交易送出
- **Then** 訂單 `channel` 為 `store`，門市庫存即時扣除，線上商品頁同步顯示最新庫存

### US-06 宴席成效報表（後續版本）
**身為**管理者，**我想要**看到每場宴席 QR code 帶來的訂單數與營收，**以便**評估哪些宴席與菜色最能帶動銷售。

### US-07 新人伴手禮禮盒（後續版本）
**身為**新人，**我想要**大量訂購調理包禮盒並指定配送日期，**以便**當作婚宴謝禮。

## 4. 成功指標（待確認）

| 指標 | 定義 | 上線 3 個月目標（草擬） |
| :--- | :--- | :--- |
| QR 掃碼轉換率 | QR 落地頁造訪者中完成訂單的比例 | ≥ 5% |
| 每場宴席帶動訂單數 | `channel = 'qr'` 的訂單數 ÷ 宴席場次 | ≥ 3 筆 / 場 |
| 90 天回購率 | 首購後 90 天內再次購買的會員比例 | ≥ 20% |
| 超賣件數 | 付款成功但無庫存可出貨的訂單數 | 0 |
| 冷凍配送客訴率 | 退冰、破損客訴訂單 ÷ 宅配訂單 | ≤ 1% |
| 結帳完成時間 | 從加入購物車到付款完成的中位數（手機） | ≤ 3 分鐘 |

## 5. 範圍與優先順序

### MVP（第一階段，學期內完成）
| 優先 | 功能 | 對應 User Story |
| :--- | :--- | :--- |
| P0 | 商品列表與商品頁（含完整食品標示） | US-02 |
| P0 | 購物車、結帳、綠界付款（測試環境） | US-02 |
| P0 | 庫存保留與扣除（防超賣） | US-02、US-05 |
| P0 | 喜宴 QR 落地頁與來源追蹤 | US-01 |
| P1 | 會員登入（手機 OTP）與訂單查詢 | US-04 |
| P1 | 門市自取與核銷 | US-03 |
| P1 | 點數累積與折抵 | US-04 |
| P2 | 簡易門市 POS | US-05 |
| P2 | 後台：商品上架、庫存調整、訂單管理 | — |

### 後續版本
- 宴席成效報表與菜色銷售分析（US-06）
- 新人伴手禮禮盒與指定日期配送（US-07）
- LINE Login 與 LINE 官方帳號推播（到貨通知、節慶促銷）
- 年菜預購檔期與預購庫存
- 多會館、多門市擴充

### 不在範圍內
- 常溫商品、生鮮食材販售
- 第三方電商平台（蝦皮、momo）串接
- 實體物流車隊管理

## 6. 假設與待確認問題
1. 合作會館能提供的菜色品項、批量產能與食品檢驗報告。
2. 冷凍物流業者與運費計算方式（依重量、溫層或件數）。
3. 付款期限（目前草擬 30 分鐘）與宴席優惠的折扣幅度。
4. 點數回饋比例與有效期限。
5. 會館是否已有 POS 系統需要串接，或使用本系統的簡易 POS。
